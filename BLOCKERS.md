# Blockers

Things that need a real external credential or machine. Each one is built against a fake behind the same interface, and the tests use the fake.


- **Real model providers (M2).** The OpenAI, Anthropic and Google adapters are tested only against local mock servers that speak each API's wire format; no real API key was available. To use one for real: store the key in the vault as `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` or `GOOGLE_API_KEY` (or point `keySecret` at your own name), and the default aliases start using it.
- **Real MCP OAuth provider registration (M10).** PKCE, single-use authorization codes and user/workspace state binding are exercised through a fake provider. There is no deployed OAuth client registration for third-party servers. Supply an existing provider token through the vault for HTTP connections, or implement the `OAuthProvider` interface with your registered provider before exposing a production authorization flow. The `/fake/` routes identify their results as test-only.
- **Windows companion on a real desktop (M12).** The Go companion is tested against a mock tunnel server and the in-memory desktop driver, and against the real server with `--fake-driver`. The real Windows driver was smoke-tested read-only on a Windows 11 machine (screen capture, window list, banner window and hotkey registration); real clicks and typing into another person's desktop were not exercised by automation. Try it on a spare machine first: pair, share one app, and use **Companion → Take a screenshot**, then an enabled agent.
- **Store integrations with real accounts (M12).** The Shopify, Mercado Pago and Meta (ads insights, Instagram publishing) adapters are tested against local mock servers that follow the public API docs; no real store, payment or ad account was available. To run the daily report on real data, add `SHOPIFY_SHOP`, `SHOPIFY_TOKEN`, `MERCADOPAGO_TOKEN`, `META_AD_ACCOUNT`, `META_TOKEN` and `INSTAGRAM_USER_ID` to the vault and call `POST /packs/store-operator/simulate {"real": true}`.
- **install.sh on a real VPS (M12).** Tested end to end in a clean Ubuntu 24.04 container (Docker inside, images loaded from a tarball, HTTPS with Caddy's local CA for `localhost`). A public domain with Let's Encrypt certificates, systemd and the nightly cron job were not exercised; on a real server they use the same code paths with a public DNS name.

Additional real-Windows checks for the M12 review: confirm screenshot masking with moving/overlapping shared and unshared windows, and verify that local share/power changes stop live input on the actual desktop. Fake-driver and configuration-watch regressions pass; they do not replace the existing real-desktop blocker.
