# Decisions

One line each: decision, reason.

- Repo lives in `NorthBots/northbot/` next to the build prompt, so the prompt file stays out of the repo.
- Node 22 is the target (Docker images, CI, `engines`); local dev also runs on Node 24, which is compatible.
- zod 3 (not 4) with `fastify-type-provider-zod@4`, because that pairing gives zod validation + OpenAPI generation from one schema.
- Workspace packages export TypeScript source (`exports: ./src/index.ts`); the server is bundled with tsup, which inlines them, so no per-package build step.
- The first migration is a hand-written `CREATE EXTENSION vector`, and later migrations are generated by drizzle-kit.
- Migrations run on boot under a Postgres advisory lock, so several server instances can start together safely.
- Web container is nginx serving the Vite build and proxying `/api/*` (prefix stripped) and `/v1/*` to the server, which keeps one origin for cookies.
- Server tests run against the real compose Postgres (no mocks for the DB), one file at a time.
- Acceptance scripts are bash; on Windows they run under Git Bash.
- `events` has a `workspace_id` column beyond the spec's list, because every read is scoped to one workspace.
- Live event delivery uses a Postgres trigger + `NOTIFY nb_events`, so events written by any instance (or SQL) reach every WebSocket.
- Event replay `?from=<id>` is inclusive, so "replay from id 50" includes event 50.
- Only `user.note` events are client-writable over HTTP; all other types are written by the server.
- Argon2id via `@node-rs/argon2` (prebuilt binaries, no node-gyp) with OWASP parameters (19 MiB, t=2).
- Sessions: a random 32-byte token sits in an httpOnly cookie, and only its sha256 is stored.
- Passkey login uses discoverable credentials (no email needed). Challenges live in Postgres and are single-use, 5 min TTL.
- Vault subkeys are derived per workspace with keyed BLAKE2b over the master key. libsodium is loaded via its CJS build.
- "Use in sandbox" goes through a `SecretSink` interface. M1 ships an in-memory sink, and M3 wires the real container sink.
- A software ES256 WebAuthn authenticator (`apps/server/src/auth/soft`) drives passkey tests and is reused for vault signing in M11.
- Acceptance logic is written as Node `.mjs` scripts called from `mN.sh` (fetch + ws), which is more robust than curl for cookies and WebSockets.
- Provider adapters use the official SDKs (`openai`, `@anthropic-ai/sdk`, `@google/genai`) and are tested offline against local mock HTTP servers.
- Anthropic: never send `temperature`/`thinking` budgets (current Claude models reject them); `effort` is the control. Server-side refusal fallback (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`) is on by default for the first-party API and off when a custom `baseUrl` (proxy) is set.
- Assistant turns carry `raw` provider content; the Anthropic adapter replays it unchanged on the same provider+model, so Claude thinking blocks stay valid (agent loops must be append-only and keep the system prompt frozen).
- Default aliases: `northbot-smart` = claude-opus-5-5 > gpt-4.1 > gemini-2.5-pro; `northbot-fast` = claude-haiku-5-5 > gpt-4.1-mini > gemini-2.5-flash. Targets without a vault key are skipped.
- Non-Anthropic prices in the built-in table are best-effort defaults; every row can be overridden in `settings.llm.pricing`. Unknown cloud models are priced high ($10/$50 per M) so caps still bite.
- Budget caps are checked before each call against `llm.call` event costs: spent >= cap blocks. A single call can overshoot a cap; the next one is refused. Scopes: workspace/day, API key/day, agent/day (workspace timezone), task (whole task).
- PII redaction (email, CPF, CNPJ, Luhn-valid cards, phones) runs only for `cloud` providers and is reversed in replies; raw provider turns are dropped when redacting because they hold unredacted text.
- The fake provider is stateless: script turn i answers the request holding i assistant messages, so agent runs replay identically.
- Router fallback triggers on any provider error (network, 4xx, 5xx); streams fall back only before the first chunk is emitted.
- /v1 routing hints: `x-northbot-{privacy,agent-id,task-id,task-budget-usd}` headers or `metadata.northbot_*`. Errors use the OpenAI error shape: 402 budget, 403 privacy, 404 model, 502 all providers failed.
- `/v1/responses` is basic: non-streaming text in/out (streaming returns 400 pointing to chat completions).
- API keys are `nb_` + 24 random bytes; only sha256 is stored; shown once at creation; scope `llm` required for /v1.
- The `agents` table landed in M2 (needed for per-agent budgets) with the spec's columns.
- The server reaches agentd through `docker exec -i ... bridge.mjs` (JSON lines over stdio), not the network. That works the same from the host (Docker Desktop cannot route to container IPs) and from the server container, and leaves zero listening ports on the agent's network.
- agentd runs as root on a root-only unix socket (0600) plus a per-boot token readable only by root. Shells run as uid 1001 `agent` via node-pty, so the agent's own terminal cannot reach agentd or read the browser profile (`/home/agent/.northbot-browser`, root 0700).
- Chromium runs headless with `--no-sandbox` (Playwright's default in containers). The container itself is the sandbox: cap-drop ALL (plus SETUID/SETGID/CHOWN/DAC_OVERRIDE/FOWNER/KILL for agentd), no-new-privileges, pids/memory/cpu limits.
- Egress: each agent gets its own `internal: true` Docker network, so there is no route out. A shared `egress` proxy container joins every agent network (alias `egress`). Agents use HTTP(S)_PROXY with per-sandbox credentials (only a sha256 is stored). The proxy writes `egress` events straight to Postgres. HTTPS is a CONNECT tunnel: host and port are logged, content is never seen.
- One Docker network per agent means the default Docker address pools cap a host at about 30 agent computers. Raise `default-address-pools` in the daemon config for more.
- Hibernate is `docker pause`: processes, shells and open tabs survive as they are. Snapshot is `docker commit` plus a copy of the home volume (the computer is paused during the copy).
- Command timeouts use coreutils `timeout -k 2`, where exit 124 means timed out. Output is capped at 1 MiB per stream. Logged commands and output previews are run through `scrubSecrets`.
- Vault "use in sandbox" passes the value through the docker exec environment, never on a command line, so it never reaches events. `env` mode writes ~/.northbot/secrets/NAME and an export line in ~/.bashrc.
- The server container runs as root with the Docker socket mounted, which is required to manage agent computers. That makes it as trusted as the Docker host.
- Take over: the live screen WebSocket forwards mouse and text input as CDP `Input.*` only after a `takeover` message. Takeover and release are events, and the agent runtime (M4) pauses tool calls while a human has control.
- Node 22 in the agent image is copied from the official node image (no curl|bash installers). Playwright/node-pty versions resolve at image build (no lockfile inside the image).
